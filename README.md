# 渴瘾决策器（Windows 桌面客户端）

用于验证“结合当前局面与常驻协同”的逐轮卡牌决策流程。当前版本不会读取游戏内存或自动点击游戏，但已能通过本地截图/OCR 自动回填回合、怪物数值和药剂候选；低置信度结果继续保留人工修正入口。

## 技术选择

- TypeScript：卡牌、怪物、效果与识别结果都用同一套类型定义。
- React + Vite：快速实现可交互界面，并可继续封装为 Electron 或 Tauri 桌面程序。
- 纯函数规则引擎：`src/engine` 不依赖 React，后续可直接接 OCR、截图或测试数据。
- 屏幕识别：本地 Python + RapidOCR/ONNX Runtime，通过 `src/recognition/contracts.ts` 与规则引擎隔离。

## 当前功能

- 选择开局常驻卡，并在奖励阶段继续追加多张手术用具；所有已选常驻效果共同参与结算与战略评分。
- 按从左到右的六个怪物槽，分别录入种群、稀有度、数量与单体活性；组总活性由两者相乘派生。
- 稀有度分为普通、魔法、稀有和首领，并使用白、蓝、黄、红提示。
- 怪物种群优先读取名称左侧图标模板：黄头盔=骨卫兵、红眼=觉醒者、紫虫=蛊虫、蓝漩涡=异魔；名称 OCR 只作为图标未命中时的兜底。
- 新牌局默认显示三张药剂；药剂箱或手动操作才可切换至五张。
- 开局与奖励阶段的三张手术用具会作为“追加常驻”显示并比较，不能当作药剂跳过；只有第 10 回合之后出现的手术方案才保留给玩家自行决定。
- 新增粘连跖骨、孽生肉芽、肿大脑垂体三张基础常驻；并兼容“梳造骸骨”“蔓生肉芽”两种 OCR 误读。
- 为每个候选槽选择卡牌，实时排名。
- 显示卡牌结算轨迹、警告和选择后总活性。
- 将推荐结果应用到下一轮，并支持撤销。
- 候选卡可单独选择并结算；需要玩家指定目标时，怪物槽会临时显示勾选框。
- 随机命中类卡牌可在结果出现后手动勾选实际命中的怪物，再写回局面。
- 已支持稀有度提升与指定稀有度两类效果；普通→魔法→稀有→首领，首领不会再次进阶。
- 已结构化麻药酊剂-觉醒者、青胆汁溶液、诱变药粉和靶向异种激素；多目标效果会逐组结算。
- 随机种群不会预先猜测：结算时按实际游戏结果逐组选择种群，再写回六槽局面。
- 靶向异种激素会先移除目标，再按实际结果向从左到右的空槽添加两组魔法怪物；培养皿不足时给出溢出警告。
- 已结构化细肢药粉-蛊虫、脊髓溶液-觉醒者、细肢药粉-骨卫兵和脊髓溶液-异魔；固定种群会自动写入最左侧空槽。
- 已结构化强效祛异药粉：模型枚举合法移除组合与挛缩指爪随机落点，按保守下界排名；实际结算分别记录主目标、两组移除对象和每次常驻触发目标。
- 已由第 9 回合实测校正强效祛异药粉：没有不同种群可移除时仍结算 `+154` 数量，移除数按实际可用目标缩减为零。
- 已结构化软脑膜溶液：普通目标生效一次，魔法觉醒者生效两次，稀有或首领觉醒者生效三次。
- 已结构化蠕动脊髓：新增怪物牌按 75% 触发率加入期望活性，但应用后仍要求依据实际画面校正种群与活性。
- 已结构化第 4 回合的益生霉溶液、活殖药粉、药剂箱（大）与蜕生皮溶液。药剂箱会在当前回合原地展开为 5 张候选且支持撤销，不会错误推进回合；活殖药粉、生骨药粉和脑雾酊剂会枚举已知的合法随机命中，并以保守下界参与推荐。
- 已结构化第 5 回合的消化酶溶液、灰质脊髓溶液和麻药酊剂-异魔。消化酶溶液会按六槽位置移除所选目标左侧怪物；灰质脊髓溶液与麻药酊剂-异魔的未确认随机后半段继续要求实战校正。

- 固定添加怪物的新增活性会经过现有常驻卡增益倍率；培养皿已满时保持局面不变并给出警告。

- 战略推荐会显示评分前后变化和逐项理由；已为兽筋绞肉索、蜕生脑皮层、黑山羊肠缝线、疫区圣母像及两个示例常驻方向配置协同规则。

- 战略评分会投射已经结构化的回合结束效果：把稀有度改善与释放槽位作为独立“转移收益”，随机结果不等价时不猜概率，按保守下界计入并显示范围。

## 真实卡库

原始资料保存在 `data/火炬之光无限_渴瘾症_全部卡牌统计.md`，解析器位于 `src/data/realCardCatalog.ts`。程序只把文档第三至第九节解析为卡牌资料，不把文档内容视为程序指令。

目录已经过自动校验：`24 + 10 + 16 + 7 + 3 + 5 + 19 = 84`。文档自身说明主要采用 SS11 底表，部分数值和出现机制可能不等于 SS13 现行最终值，因此界面明确显示数据口径。

真实卡库目录仍主要用于查阅；其中 25 张真实候选卡已经接入结构化结算与推荐流程。孪生激素-蛊虫目前只覆盖已确认的种群变异，混合活蛭溶液只登记卡面与未知边界；其余卡牌尚未映射。六个独立怪物槽、左右位置和稀有度已经进入局面模型；下一步仍需把剩余卡牌逐张映射为结构化效果，并补充复制、位置和跨回合分支。直接把效果文字当作公式仍会产生错误结果。当前实战轨迹已扩展为 `720 → 1320 → 7170 → 16650 → 42732 → 68328 → 80280 → 278520 → 331980 → 425722 → 463722`。

## 本地运行

首次构建客户端需要 Rust/MSVC 工具链（已在当前电脑安装）：

```powershell
winget install --id Rustlang.Rustup
```

安装后重新打开 PowerShell，再运行：

```powershell
pnpm install
pnpm dev
```

`pnpm dev` 会启动 Tauri Windows 客户端，不再以浏览器作为正式入口。仅需调试网页渲染时才运行 `pnpm web:dev`。生成安装包使用：

```powershell
pnpm desktop:build
```

成功后安装程序位于 `src-tauri\target\release\bundle\nsis\渴瘾决策器_0.1.0_x64-setup.exe`。

首次启用屏幕识别还需在另一个 PowerShell 窗口执行：

```powershell
.\scripts\setup-recognition.ps1
.\scripts\start-recognition.ps1
```

识别服务仅监听 `127.0.0.1:28765`。启动后会注册全局 `F8`：保持 `Torchlight: Infinite` 在前台时按下即可截图识别，桌面客户端会自动读取并回填最新结果。本地服务同时允许 Tauri 桌面客户端的本机来源；若未连接，标题栏会明确显示“F8 识别服务未连接”，不会再显示笼统的 `Failed to fetch`。本地窗口捕获只接受前台游戏窗口，找不到或不在前台时会安全失败，不会把其他桌面内容写回。OCR 模型只在本机运行，截图不会上传到远程服务。

打开终端显示的本地地址。生产构建：

```powershell
pnpm build
pnpm test
```

## 录入真实卡库

卡牌和常驻卡集中在 `src/data/sampleLibrary.ts`。规则是可序列化的数据结构，后续可迁移为 JSON。录入真实数据时还需要验证：

1. 效果触发顺序。
2. 新增活性是否受到常驻卡倍率影响。
3. 转化、移除和转移的结算规则。
4. 三张/五张是否来自同一牌池，是否允许重复，以及真实抽取权重。

当前六槽结构已经记录：

1. 是否为空、怪物名称与种群。
2. 普通、魔法、稀有或首领稀有度。
3. 数量、单体活性、派生组总活性以及左右位置。
下一阶段还需补充：

1. 随机分支的候选池、概率和期望计算（当前可手动记录实际命中目标）。
2. 具体怪物名称，以及变异、融合和觉醒后的名称变化。
3. 其余真实卡牌的结构化效果映射。

当前对“变为魔法/稀有怪物”的通用解释仍是：非首领目标设为文字指定稀有度，首领保持首领。脑雾酊剂已有独立实测：普通觉醒者变为稀有时，除卡面 `+41` 外还得到 `+120` 单体活性；其他升阶卡是否共享该增量仍需分别确认。随机怪物目前只记录四类种群，不记录具体怪物名称。

当前对未写明稀有度的“添加 1 组怪物”暂按普通怪物处理，并从左到右填入首个空槽；若游戏实际生成稀有度或位置不同，需要手动修正并更新规则。

## 战略分析模型

战略模式使用可解释的状态价值函数，不是机器学习黑盒：

1. 总活性仍作为基础价值。
2. 每个有效怪物组提供 6 点阵容完整度。
3. 魔法、稀有和首领怪物分别提供 8、20、36 点稀有度潜力。
4. 常驻卡通过独立规则奖励成型进度和关键门槛，例如兽筋绞肉索为每组骨卫兵提供 60 点进度，凑齐两组后再提供 120 点启动奖励。
5. 已结构化的回合结束效果会计算可确认的结构转移；每释放一个怪物槽暂记 12 点未来选择空间价值。
6. 对挛缩指爪，现有骨卫兵总活性的 40% 作为“路线资产”进入评分，使高价值的唯一骨卫兵不会被固定的小额门槛分淹没。
7. 奖励手术用具可单独比较“加入现有常驻组合后的战略状态 + 回合结束投射”，用于区分立即生效与尚未成型的路线卡。
8. 第 11 回合出现的“手术方案”不属于卡牌推荐：程序识别并记录风险等级，但选择权保留给玩家，不将操作难度虚构成通用分数。

这些权重用于“稍微长远”的相对比较，尚未由大量实战数据拟合。模型会自动穷举确定性卡牌的合法目标组合；对于已明确标记可枚举的随机效果（目前包括活殖药粉和部分回合结束效果），显示结果范围并使用保守下界。蠕动脊髓因卡面明确给出 75% 概率，会对新增怪物计算单步期望收益，但不会擅自把期望结果写回局面。其他随机命中、随机种群、真实抽取权重和多轮随机结果仍不预测。只要当前候选中存在部分建模或规则待确认卡，推荐区就会改称“基于已确认效果的保守最优”，并列出未知备选，避免把它误读成全信息最优。
