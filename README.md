## 一键启动（本机）

- 桌面双击“启动渴瘾决策器.cmd”：先校验28765端口占用者为当前项目recognizer/server.py的python.exe，且父进程可执行文件为项目.venv-recognition/Scripts/python.exe；全部校验通过才结束旧服务，再后台调用scripts/start-recognition.ps1，健康后打开客户端。已有客户端不重复打开。服务不依赖启动窗口。
- “管理员启动渴瘾决策器.cmd”会请求Windows UAC授权，用于游戏/旧服务以管理员权限运行的情况。按相同校验重启服务，新服务继承管理员权限。路径、命令行不可读或不匹配则停止，不误关其他程序；原客户端若已运行，保持其原权限。
- 日志：`%LOCALAPPDATA%\VoraxDecisionAssistant\logs`。每次启动会重启通过校验的服务，尚未完成的点牌监听会清空；局面存档、名字典不受影响。端口异常/权限不足/文件缺失会报错，不覆盖用户数据。
- 项目内入口为`start-installed.cmd`，脚本为`scripts/start-installed.ps1`；默认客户端`D:\渴瘾决策器\vorax-decision-assistant.exe`。服务路径跟随项目目录。移动项目后需更新桌面cmd中的项目路径；更换客户端目录可传`-ClientPath "新路径\vorax-decision-assistant.exe"`。
- 只检查路径及已有服务、不启动任何进程：`powershell -NoProfile -File scripts/start-installed.ps1 -CheckOnly`。

## 技术选择

- TypeScript：卡牌、怪物、效果与识别结果都用同一套类型定义。
- React + Vite：快速实现可交互界面，并可继续封装为 Electron 或 Tauri 桌面程序。
- 纯函数规则引擎：`src/engine` 不依赖 React，后续可直接接 OCR、截图或测试数据。
- 屏幕识别：本地 Python + RapidOCR/ONNX Runtime，通过 `src/recognition/contracts.ts` 与规则引擎隔离。

## 当前功能

- 单次识别：游戏画面稳定后按F8，读取怪物、回合、三/五张候选和可靠洗牌次数；按键按住与多通道重复事件去重，处理中的重复请求不再新增任务。持续观察线程不启动，旧/follow/start接口拒绝开启。
- 浮窗截图时使用单次避让路径，截图后恢复但不抢焦点；结果保留到下一次识别。仍支持导入图片。
- 选择记录：监听当前F8牌面的物理左键点击，不监听其他程序/鼠标移动/文字，不拦截或注入输入。只接受游戏前台且鼠标落在游戏窗口上的点击；三/五牌位置锚定OCR标题，点击重选覆盖暂选，点确认后冻结，下一次F8校验。鼠标目标只记为点击槽位，不当作随机落点。确认区采用已校验16:9布局的窄范围，其他比例/低可信/重叠位置禁用监听。
- 最近100条选择及常驻组合共同写入原v4局面存储，重复轮询/刷新不重复追加。历史面板显示最近8条，可人工确认或标记误记；误记已追加常驻需在完整界面取消勾选。未匹配准确名称/显式别名的常驻不会自动添加。原浮窗“已选”、完整界面“选择并追加”和左侧勾选仍可用。

## 战略分析模型

战略模式使用可解释的状态价值函数，不是机器学习黑盒：

1. 总活性仍作为基础价值。
2. 每个有效怪物组提供 6 点阵容完整度。
3. 魔法、稀有和首领怪物分别提供 8、20、36 点稀有度潜力。
4. 常驻卡通过独立规则奖励成型进度和关键门槛，例如兽筋绞肉索为每组骨卫兵提供 60 点进度，凑齐两组后再提供 120 点启动奖励。
5. 已结构化的回合结束效果会计算可确认的结构转移；每释放一个怪物槽暂记 12 点未来选择空间价值。
6. 对挛缩指爪，现有骨卫兵总活性的 40% 作为“路线资产”进入评分，使高价值的唯一骨卫兵不会被固定的小额门槛分淹没。
7. 奖励手术用具可单独比较“加入现有常驻组合后的战略状态 + 回合结束投射”，用于区分立即生效与尚未成型的路线卡。
8. 第 11 回合出现的“手术方案”不属于卡牌推荐：程序识别并记录风险等级，但选择权保留给玩家，不将操作难度虚构成通用分数。

这些权重用于“稍微长远”的相对比较，尚未由大量实战数据拟合。模型会自动穷举确定性卡牌的合法目标组合；对于已明确标记可枚举的随机效果（目前包括活殖药粉和部分回合结束效果），显示结果范围并使用保守下界。蠕动脊髓因卡面明确给出 75% 概率，会对新增怪物计算单步期望收益，但不会擅自把期望结果写回局面。其他随机命中、随机种群、真实抽取权重和多轮随机结果仍不预测。只要当前候选中存在部分建模或规则待确认卡，推荐区就会改称“基于已确认效果的保守最优”，并列出未知备选，避免把它误读成全信息最优。
